我用 S7-1500 和 ET 200SP 完成了 PROFINET **离线组态**、8DI/8DQ 地址映射，以及电机启停自锁和运行灯程序。

> **验证范围：**PLC 软件编译 **0 错误、0 警告**。尚未验证真实 PROFINET IO 在线通信，未确认硬件整体编译通过；以下截图记录的是离线配置和程序。

## 先看成果｜启停自锁与运行灯

![LAD 程序：xStart 与 xMotorRun 并联自锁，串联 xStop 常闭逻辑触点，运行灯跟随电机运行状态](/images/posts/e-p1-profinet/07-lad.png)

启动 `xStart` 后，`xMotorRun` 通过并联触点保持；`xStop = TRUE` 时，常闭逻辑触点断开并解除自锁。第二段让 `xRunLight` 跟随 `xMotorRun`。

这里的常闭触点是 **LAD 逻辑取反**，不能据此判断现场按钮的接线形式；实体接线和信号极性还需要现场核对。本次没有做实体电机、按钮和远程输出联调。

![PLC_1 程序块 Main OB1 软件编译完成：0 错误、0 警告](/images/posts/e-p1-profinet/08-software-compile.png)

这张编译结果确认的是 **PLC 软件**，不代表硬件整体编译通过，也不证明远程 I/O 已在线交换数据。

## 基础故障排查｜下一步在线验证时使用

下面是我整理的核对顺序，**尚未作为实机故障测试完成项**。

| 现象 | 优先核对 |
| --- | --- |
| 找不到远程站 | 供电、网线、端口、所选网卡和可访问设备 |
| 能找到设备，但没有 IO 数据交换 | 实际 PROFINET 设备名是否与组态一致，IP / 子网及 IO 控制器分配 |
| 站点或模块出现诊断 | 实际订货号、固件、插槽顺序、基座、电位组和模块供电；读取在线诊断详情 |
| 输入或运行灯没有响应 | 模块起始地址、变量引用、停止信号极性、输出覆盖及实际接线 |

下一步需要在真实硬件或支持相应 IO Device 的环境中，完成设备名分配、在线诊断和输入输出联调。**当前成果停在离线组态与软件编译，真实 PROFINET IO 在线通信尚未验证。**

## 补记｜PROFIBUS DP：同一件事的另一套做法

PROFINET 这套组态做完，我又把 PROFIBUS DP 补了一遍。不是我设备上真跑过，而是把「连接、终端、站号」这三件事对着手册和实物照片捋清楚——现场看到一根紫缆、一个 9 针接头、一排拨码，至少知道该查哪儿。

### 1. 连接：一根紫色电缆串到底

![PROFIBUS 总线接头：9 针 D-sub，进、出两根电缆接在同一个接头上，红色小拨钮是终端电阻开关](/images/posts/e-p1-profinet/09-profibus-connector.png)

DP 走 RS-485：两芯屏蔽电缆，现场叫紫缆，A/B 差分。接头是 9 针 D-sub，上面有两个电缆入口——**进线和出线接在同一个接头上**，站与站之间一路串下去，不是星形接到交换机。FastConnect 接头不用剥线，压接钳一压就完；图上左边和右边是两种出线方向（180° 和 90°），电气上是一回事。

### 2. 终端电阻：只在物理两端接

![PROFIBUS 总线：终端电阻只在两端 ON，中间从站 OFF；每端是 390 Ω + 220 Ω + 390 Ω](/images/posts/e-p1-profinet/10-profibus-bus.png)

终端电阻不是"每个站都加"，而是**只在总线两个物理末端接**：

- 两端：拨钮打到 ON，390 Ω + 220 Ω + 390 Ω 接入，给总线一个确定的特性阻抗；
- 中间站：两个拨钮都 OFF，电缆在接头内部直通，只进不出。

只开一端，另一端悬空，信号到末端会反射，表现为偶发丢站、诊断里报总线故障；中间站误开 ON，等于给总线多并一个负载，整段都会变差。图 1 里接头上那个红色小拨钮就是干这个的。这一段离线完全看不出来，只有现场量 A-B 之间的直流电阻才能确认终端到底接没接上。

### 3. 站号拨码：64/32/16/8/4/2/1

![ET 200SP DP 接口模块的站号拨码：权重 64/32/16/8/4/2/1，示例 64+32+2+1=99](/images/posts/e-p1-profinet/11-profibus-address.png)

DP 没有"设备名"，靠**站地址**找设备：1～125，同一条总线上不能重复。地址用拨码按二进制设，权重是 64、32、16、8、4、2、1，图上示例 64+32+2+1=99。改完站号要重新上电才生效，这一点和 PN 不一样——PN 改设备名是在线操作，不用断电。

### 4. 在 TIA 里做一遍离线组态

手上的 1511-1 PN 没有 DP 口，所以要加一块 **CM 1542-5** 当 DP 主站：

1. 硬件目录里把 CM 1542-5 拖到 CPU 右侧空槽，新建 `PROFIBUS_1` 子网，设为主站，波特率先给 1.5 Mbit/s（按从站支持取）。
2. `选项 → 管理通用站描述文件`，装从站的 **GSD**。它是文本文件，不是 PN 的 GSDML（XML）；ET 200SP 的 IM 155-6 DP HF 在目录里自带，第三方从站必须自己装。
3. 把从站拖到 `PROFIBUS_1` 上，站地址设 3，和拨码一致。
4. 按 GSD 的模块表放模块，记下 I/O 起始地址（DP 从站常见 256 起，和 PN 那边的 %I0.0 不冲突，变量要重新分配）。
5. 硬件编译 0 错误；下载后在线诊断看从站是否可达、模块是否和组态一致。

### 5. PN 和 DP 差在哪

| 维度 | PROFINET IO | PROFIBUS DP |
| --- | --- | --- |
| 物理层 | 工业以太网，RJ45/FC，100 Mbit/s | RS-485 紫缆，9 针 D-sub，9.6 k～12 Mbit/s |
| 找设备靠 | 设备名 + IP | 站地址（拨码） |
| 描述文件 | GSDML（XML） | GSD（文本） |
| 通信方式 | 生产者/消费者，可过交换机 | 主站轮询从站 |
| 拓扑 | 星/线/环 | 总线，干线加短支线 |
| 终端 | 不需要 | 两端 390/220/390 Ω |
| 改地址 | 在线改名，不必断电 | 拨码，重新上电生效 |

### 6. 这一段停在哪儿

上面全部是**离线组态 + 资料核对**。编译 0 错误只说明组态自洽，证明不了站地址真的对上、终端真的只开了两端、紫缆有没有接反、从站是不是真的在总线上。DP 的在线验证必须有实机总线，我没有，所以这一段标「认识 + 离线组态」，不标「已掌握」。
