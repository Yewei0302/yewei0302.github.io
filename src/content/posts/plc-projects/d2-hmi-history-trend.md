B2已经能够显示温度实时曲线，D1补充了报警管理。D2继续使用同一套恒温系统，重点学习如何把过程数据保存下来，再通过HMI和CSV查看已经发生的过程。

这次没有增加新的PLC控制逻辑。现有的实际温度、设定温度和加热输出就是数据源，主要工作集中在WinCC的数据记录、历史趋势和存储配置。

## 1. 历史趋势运行效果

![历史趋势显示升温过程、55℃设定值和逐渐降低的加热输出](/images/posts/d2-hmi-history-trend/01-history-running.png)

黑线是实际温度，红线是设定温度，蓝线是加热输出。温度从约25℃向55℃上升，加热输出先增大，再随着温度接近目标逐渐降低，稳定阶段约为20%。

温度和输出的单位不同，因此使用左右两条数值轴：左侧为℃，右侧为%。虽然这次两边都设为0～100，读图时仍要区分量纲。

| 项目 | 配置 |
|---|---|
| 工程名称 | `D2_HMI_TrendArchive` |
| 基础工程 | B2房间恒温PID，沿用D1报警功能 |
| 编程环境 | TIA Portal V19 |
| PLC | S7-1500 CPU 1511-1 PN，软件仿真 |
| HMI | PC站，WinCC RT Advanced |
| 记录名称 | `Log_RoomTemp` |
| 文件格式 | CSV文件（ASCII） |
| 记录变量 | 实际温度、设定温度、联锁后的加热输出 |
| 记录周期 | 三个变量均为1秒 |
| 历史趋势窗口 | 600秒，即10分钟 |

## 2. 先分清“读取、保存、显示”

实时曲线能动，只能说明画面正在取得数据。要让这些数据可以回看，还需要配置记录及其存储位置。

| 环节 | 作用 | 需要关注的设置 |
|---|---|---|
| HMI变量采集 | 从PLC取得过程值 | 连接、变量地址或符号、采集周期 |
| 数据记录 | 把过程值按规则写入记录 | 记录变量、记录周期、文件路径、容量 |
| 趋势显示 | 将当前值或记录值画成曲线 | 趋势类型、数据源、时间窗口、数值轴 |

采集周期、记录周期和画面刷新不是同一个概念。把趋势窗口设为10分钟，也不表示文件只能保存10分钟；窗口决定一次看多长，记录容量与记录频率决定能保留多少数据。

## 3. 创建Log_RoomTemp数据记录

在本机界面中，入口是项目树下的 **HMI_RT_1 → 记录 → 数据记录**。一些旧版教程将入口称为“历史数据”，实际操作时需要对照当前软件界面。

![数据记录与三个记录变量的配置](/images/posts/d2-hmi-history-trend/02-data-log.png)

上半部分定义记录本身，下半部分定义哪些变量写入这份记录。

| 配置项 | 本次做法与含义 |
|---|---|
| 名称 | `Log_RoomTemp`，用于关联趋势数据源 |
| 存储位置 | 选择CSV文件（ASCII），方便查看保存结果 |
| 路径 | 指定电脑上的实际保存目录 |
| 记录方法 | 循环记录，容量达到上限后逐步替换旧数据 |
| 运行系统启动时启用记录 | 勾选，Runtime启动时开始记录 |
| 每个记录的数据记录数 | 决定容量；图中的组态值为1000 |

循环记录适合保留最近一段过程，但它不是无限期保存方案。需要更长历史时，应结合变量数量、记录周期和磁盘空间增加容量，或进一步设计分段与备份。

本次使用PC运行系统，保存路径是运行WinCC的电脑目录。面板教程中的U盘或存储卡路径不能原样照搬到PC工程。

### 关联三个过程变量

| 记录变量名称 | 过程变量 | 单位 | 采集模式 | 记录周期 |
|---|---|---|---|---|
| `Log_TempPV` | `rRoomTempPV` | ℃ | 循环 | 1 s |
| `Log_TempSP` | `rRoomTempSP` | ℃ | 循环 | 1 s |
| `Log_HeatOut` | `rHeaterOutSafePct` | % | 循环 | 1 s |

这里记录的是 `rHeaterOutSafePct`，即经过联锁处理后的输出。它能反映停止或故障时加热被禁止的结果，比只记录PID内部计算输出更适合这次实验。

## 4. 让趋势读取记录数据

新建 `Scr_D2_History` 画面，放入“趋势视图”，主画面增加“历史记录”入口，历史画面保留返回按钮。

![三条趋势均选择数据记录，加热输出使用右侧值轴](/images/posts/d2-hmi-history-trend/03-trend-config.png)

这一步的关键是把三条曲线的“趋势类型”设为 **数据记录**。然后打开每一行的“源设置”，选择 `Log_RoomTemp` 和对应过程值。

| 曲线 | 数据记录 | 源设置中的过程值 | 数值轴 |
|---|---|---|---|
| 实际温度 | `Log_RoomTemp` | `rRoomTempPV` | 左 |
| 设定温度 | `Log_RoomTemp` | `rRoomTempSP` | 左 |
| 加热输出 | `Log_RoomTemp` | `rHeaterOutSafePct` | 右 |

本机数据源对话框显示的是“过程值”，选择原有HMI变量名；它与记录编辑器里填写的 `Log_TempPV` 等名称不是同一个字段。配置时要看数据关联，而不是只凭名称是否相同判断。

### 时间轴与工具栏

![时间轴设为600秒，显示十分钟范围](/images/posts/d2-hmi-history-trend/04-time-axis.png)

左右值轴都设为0～100，时间间隔设为600秒，并显示工具栏。运行后可以暂停刷新、翻看前面的时间段、缩放和使用标尺查看数值。

趋势控件的停止刷新用于固定当前查看位置，与主画面的“系统停止”是两个操作。前者不等于停止PLC，也不能据此认定后台记录已经停止。

## 5. 升温与停止过程

系统启动后，实际温度逐渐接近55℃。稳定阶段主画面显示实际温度54.9℃、加热输出20.1%，与历史趋势中的变化相对应。

![恒温运行：设定55℃，实际54.9℃，输出20.1%](/images/posts/d2-hmi-history-trend/05-steady-state.png)

按下系统停止后，运行和加热允许指示灯熄灭，加热输出回到0。温度不会立即归零，而是按照原有温度模型逐渐向环境温度回落。

![停止后输出为0，实际温度逐渐回落](/images/posts/d2-hmi-history-trend/06-stopped.png)

这次对照观察让我更容易区分“控制输出变化”和“被控对象响应”：输出可以迅速撤销，但温度变化仍然有过程。

### 回看先前的时间段

![后续回看画面：停止降温段与后续数据段处于同一时间窗口](/images/posts/d2-hmi-history-trend/07-history-review.png)

后续回看时，图中仍能查看停止后的降温段，也能看到后续数据重新出现的时间位置。

中间落到0的区段不能直接解释为房间实际降到0℃。判断这类记录，应结合当时的PLC/HMI运行状态、连接情况和CSV原始值。本次用它记录运行过程的变化，不把未确认的中断区段当成有效温度过程分析。

跨Runtime重启保留历史时，还需要关注记录的重启处理方式：追加到现有记录与重置记录会产生不同结果。正式使用前应把这一项与存储路径、循环容量一起确认。

## 6. CSV里实际保存了什么

保存目录中生成了 `Log_RoomTemp0.csv`。用记事本打开后，可以看到变量名、时间和数值等字段，三个变量按各自的记录条目写入。

![CSV原始记录：三个变量按1秒周期保存](/images/posts/d2-hmi-history-trend/08-csv.png)

以截图中的 **2026/9/27 23:35:14** 为例：

| 变量 | 保存值 |
|---|---:|
| `rRoomTempPV` | 54.54624 |
| `rRoomTempSP` | 55 |
| `rHeaterOutSafePct` | 20.59827 |

同一个时间点对应三行，而不是一行中并排放三个数值。按这次三个变量、每秒记录一次的设置，每秒约产生三条记录。记录容量不能直接等同于秒数，更不能直接当作每个变量各自拥有的点数。

### 用Excel查看的做法

1. 正常关闭Runtime，或复制一份CSV作为分析副本。
2. 在Excel中通过文本/CSV导入方式打开副本。
3. 按文件实际使用的分隔符分列，检查变量名、时间和数值是否正确分开。
4. 筛选一个变量查看，或按时间与变量名整理成对照表。

源文件由WinCC管理，分析时使用副本更方便，也能避免编辑、占用正在写入的记录文件。

## 7. 这次掌握的配置方法

完成D2后，数据链已经连通：PLC产生过程值，HMI按周期采集，数据记录负责保存，历史趋势负责回看，CSV提供进一步分析的入口。

排查时也可以按这条链分段检查：

| 现象 | 优先检查 |
|---|---|
| 主画面数值不变化 | PLC运行状态、HMI连接与变量绑定 |
| 实时值正常但没有文件 | 记录是否启用、目录是否可写、运行系统提示 |
| 文件有数据但历史趋势为空 | 趋势类型、记录及过程值关联、显示时间范围 |
| 找不到更早数据 | 循环容量、记录周期、重启处理方式 |
| 表格当前数值与曲线末端不同 | 标尺是否停在较早的时间点 |

相比继续增加控制程序，这次的收获是理解数据从哪里来、保存在哪里，以及怎样把已经发生的过程重新展示出来。后续D3将继续使用现有工程，学习配方和整组参数的保存、读取与下发。
