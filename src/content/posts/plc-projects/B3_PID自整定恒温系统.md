## 项目说明

B2项目已经完成了房间恒温PID闭环控制。本次B3不再重复研究“PID能不能运行”，而是在B2成功架构的基础上，继续学习 `PID_Compact` 的参数自整定功能：

- 预调节（Pretuning）；
- 精确调节（Fine tuning）；
- 上传并保存整定后的PID参数；
- 比较两次整定结果；
- 验证整定后控制器的冷启动和设定值阶跃响应。

本项目没有使用实体PLC和温度传感器，全部通过S7-PLCSIM与PLC内部温度模型完成。

> 本文记录的是一次完整的学习与验证过程。仿真模型的时间尺度经过加速，参数不能直接照搬到真实加热设备中。

## 一、项目环境

| 项目 | 配置 |
|---|---|
| 编程软件 | TIA Portal V19 |
| PLC | S7-1500 CPU 1511-1 PN |
| 仿真软件 | 标准版S7-PLCSIM |
| 编程语言 | LAD梯形图 |
| PID控制器 | PID_Compact |
| 周期中断 | OB30，100 ms |
| 被控对象 | 自建全局库中的FB_RoomTempSim |
| 控制目标 | 房间温度稳定在设定值 |

此前使用S7-1200配合标准PLCSIM仿真PID_Compact时，曾出现输出和状态无法正常变化的问题。B2切换到S7-1500后闭环运行成功，因此B3继续沿用已经验证过的S7-1500方案。

## 二、控制系统结构

```text
rRoomTempSP（设定温度）
        ↓
PID_Compact
        ↓
rHeaterOutPct（加热输出0～100%）
        ↓
FB_RoomTempSim（房间温度模型）
        ↓
rRoomTempPV（实际温度）
        └────────反馈给PID_Compact
```

PID_Compact和温度模型都在100 ms循环中断OB30中执行，保证PID算法采样周期与温度模型计算周期稳定一致。

## 三、全局数据块设计

全局数据块为 `DB_B3_Control`，变量遵循“数据类型小写前缀”的命名规则。

| 变量名 | 类型 | 默认值 | 含义 |
|---|---|---:|---|
| `xSimResetCmd` | Bool | false | 温度仿真模型复位命令 |
| `rRoomTempSP` | Real | 55.0 | 房间温度设定值，单位℃ |
| `rRoomTempPV` | Real | 20.0 | 房间实际温度模拟值，单位℃ |
| `rManualValue` | Real | 30.0 | PID手动模式输出，范围0～100% |
| `iPIDMode` | Int | 0 | PID目标运行模式 |
| `xModeActivate` | Bool | false | PID模式切换触发信号 |
| `xErrorAck` | Bool | false | PID故障确认命令 |
| `rHeaterOutPct` | Real | 0.0 | PID加热输出百分比 |
| `iPIDState` | Int | 0 | PID当前实际运行状态 |
| `xPIDError` | Bool | false | PID故障状态 |
| `dwPIDErrorBits` | DWord | 16#0 | PID详细故障代码 |

### PID模式值

| 数值 | 模式 |
|---:|---|
| 0 | 未激活 |
| 1 | 预调节 |
| 2 | 精确调节 |
| 3 | 自动模式 |
| 4 | 手动模式 |

写入新的 `iPIDMode` 后，必须让 `xModeActivate` 产生一次FALSE→TRUE上升沿，模式命令才会生效。

## 四、房间温度模型

温度模型复用个人全局库中的：

```text
Yewei_PLC_BlockLibrary
└─ Simulation
   └─ FB_RoomTempSim
```

| 参数 | 数值 |
|---|---:|
| 环境温度 | 20.0℃ |
| 初始温度 | 20.0℃ |
| 加热增益 | 1.5 |
| 散热系数 | 0.02143 |
| 计算周期 | 0.1 s |

稳定温度可以近似表示为：

$$
T_{stable}=T_{ambient}+
\frac{Output/100\times HeaterGain}{HeatLossGain}
$$

| 加热输出 | 理论稳定温度 |
|---:|---:|
| 30% | 约41℃ |
| 50% | 约55℃ |
| 70% | 约69℃ |
| 100% | 约90℃ |

因此55℃稳态时，PID输出应接近50%。

## 五、自整定前的手动测试

```text
iPIDMode = 4
rManualValue = 30.0
xModeActivate：FALSE → TRUE → FALSE
```

正确结果：

```text
iPIDState = 4
rHeaterOutPct ≈ 30.0%
```

如果 `iPIDState=3`，说明控制器仍处于自动模式，此时 `rManualValue` 不参与计算。设定温度55℃、实际温度20℃时，自动模式输出达到100%属于正常现象。

## 六、PID预调节

预调节会主动施加阶跃输出，观察被控对象的最大上升速度、惯性和延迟，再自动计算PID参数。

开始条件：

```text
rRoomTempSP = 55.0℃
rRoomTempPV ≈ 20.0℃
iPIDState = 0
xSimResetCmd = FALSE
xPIDError = FALSE
```

预调节过程中，输出上升到100%，温度从20℃逐渐上升。接近55℃后，控制器降低输出并自动转入自动模式。

成功标志：

```text
调节状态：系统已调节
iPIDState：1 → 3
xPIDError = FALSE
```

### 预调节参数

| 参数 | 预调节结果 |
|---|---:|
| 比例增益 | 638.7934 |
| 积分作用时间 | 0.2399957 s |
| 微分作用时间 | 0.04199924 s |
| 微分延迟系数 | 0.1 |
| 比例作用权重 | 0.8 |
| 微分作用权重 | 0.0 |
| PID算法采样时间 | 约0.1 s |
| 控制器结构 | PID |

预调节成功后，通过“上传PID参数”把仿真CPU中的在线参数保存到TIA离线项目。

## 七、PID精确调节

精确调节开始前，过程值必须已经稳定：

```text
SP ≈ 55℃
PV ≈ 55℃
Output ≈ 50%
iPIDState = 3
```

精确调节期间，PID主动使输出产生周期性跳变，温度在55℃附近出现有限振荡。输出剧烈变化属于正常现象，并不是系统失控。调节结束后，PID自动恢复自动模式。

### 精确调节参数

| 参数 | 精确调节结果 |
|---|---:|
| 比例增益 | 69.1974 |
| 积分作用时间 | 1.146506 s |
| 微分作用时间 | 0.2584207 s |
| 微分延迟系数 | 0.1 |
| 比例作用权重 | 0.5750124 |
| 微分作用权重 | 0.0 |
| PID算法采样时间 | 约0.1 s |
| 控制器结构 | PID |

## 八、两次整定结果对比

| 参数 | 预调节 | 精确调节 | 变化趋势 |
|---|---:|---:|---|
| 比例增益 | 638.7934 | 69.1974 | 显著降低 |
| 积分时间 | 0.2399957 s | 1.146506 s | 增加 |
| 微分时间 | 0.04199924 s | 0.2584207 s | 增加 |
| 比例作用权重 | 0.8 | 0.5750124 | 降低 |

精确调节后，比例作用更加温和，积分累积速度降低，微分对温度变化趋势的抑制增强。最终仍需通过阶跃响应判断参数是否有效。

## 九、20℃→55℃冷启动测试

上传精确调节参数后，将温度模型复位到20℃，再切换自动模式。

测试结果：

```text
rRoomTempPV = 55.0℃
rHeaterOutPct ≈ 50.00434%
iPIDState = 3
```

过程温度基本没有明显超调，也没有持续振荡。

## 十、55℃→45℃设定值阶跃测试

将设定值从55℃修改为45℃。因为模型只有加热器，没有主动制冷，PID首先将输出降到0%，让温度自然下降；接近45℃后重新增加输出。

最终结果：

```text
rRoomTempPV = 45.0℃
rHeaterOutPct = 35.71554%
iPIDState = 3
```

理论稳态输出为：

$$
\frac{(45-20)\times0.02143}{1.5}\times100\%
\approx35.72\%
$$

实测值35.71554%与理论值几乎完全一致。

## 十一、容易混淆的问题

### ManualValue为30%，输出为什么还是100%？

因为 `iPIDState=3` 表示自动模式。只有 `iPIDState=4` 时，`rManualValue` 才生效。

### 为什么自整定期间输出剧烈跳变？

这是控制器主动施加的测试信号。预调节利用阶跃响应，精确调节利用有限振荡识别对象特性。

### 为什么精确调节前不能复位温度？

精确调节要求过程值处于稳定状态。复位到20℃会产生很大的瞬态偏差。

### 为什么要上传PID参数？

自整定首先修改在线CPU中的参数，上传后才能将优化结果保存到TIA离线项目。

## 总结

通过B3项目，我不再只是让PID_Compact“运行起来”，而是完整经历了被控对象验证、预调节、精确调节、参数上传和阶跃响应验收。

PID自整定并不是按一下按钮就结束。开始前必须确认控制器模式、过程稳定性、设定值与过程值偏差以及输入输出范围；完成后还必须上传参数，并通过新的阶跃测试判断整定结果是否真正有效。
