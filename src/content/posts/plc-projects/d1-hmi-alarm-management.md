B2完成了房间恒温PID控制，也有超温和PID错误报警。进入D阶段后，我继续使用这套工程，把学习重点放在HMI报警的配置、显示和操作上：报警由哪个变量触发，什么时候算恢复，操作员确认后又改变了什么。

这次沿用原来的温度仿真、PID、主画面和报警画面，增加传感器故障模拟、模拟急停，完成四类离散报警的组态。结合官方视频，把原来“能够显示报警”的功能整理成一套可以复用的方法。

## 1. 实际运行效果

![D1报警运行记录：传感器故障模拟和模拟急停的事件显示](/images/posts/d1-hmi-alarm-management/01-runtime.png)

运行画面中可以看到两种模拟故障的报警文本、时间、日期和状态。操作按钮用于注入故障，报警视图用于查看事件和执行确认。

同一报警编号可以出现多条记录。阅读时要同时看时间和状态，不能只按行数判断发生了多少次独立故障。

| 项目 | 本次配置 |
|---|---|
| 工程 | 基于B2另存为 `D1_HMI_Alarm` |
| 编程环境 | TIA Portal V19 |
| PLC | S7-1500 CPU 1511-1 PN，软件仿真 |
| HMI | PC站，WinCC RT Advanced |
| 数据块 | `DB_B2_Control` |
| 画面 | `Scr_B2_Overview`、`Scr_B2_Alarms` |
| 报警来源 | 超温、PID错误、传感器故障模拟、模拟急停 |

画面保留B2的名称和布局，方便对照原工程。这里的传感器故障与急停采用软件信号模拟，用于学习报警处理和联锁关系。

## 2. 先分清PLC和HMI各自负责什么

PLC负责判断故障、锁存报警、判断复位条件，并决定是否允许运行和加热。HMI读取这些状态，显示报警文本、时间和确认状态，向PLC发送操作命令。

这次最需要分开的三个动作是：

| 动作 | 含义 | 本项目中的作用 |
|---|---|---|
| 排除故障原因 | 原始故障条件不再成立 | 例如关闭传感器故障模拟信号 |
| HMI报警确认 | 操作员确认已经看到报警 | 改变HMI侧确认状态，不直接清除PLC报警位 |
| PLC报警复位 | 满足复位条件后解除锁存 | 原故障解除后，通过 `xAlarmResetCmd` 清除报警锁存 |

本项目没有配置HMI确认变量与PLC确认位的握手。因此，点击报警视图中的确认按钮，不会自动写入 `xAlarmResetCmd`，也不会直接启动系统。

## 3. 用一个Word组织四类报警

HMI读取 `DB_B2_Control.wHMIAlarmTrigger`，按位区分报警来源。一个Word包含16个位，本次使用bit 0～3。

| 位号 | PLC报警变量 | HMI报警名称 | 含义 |
|---|---|---|---|
| 0 | `xRoomTempHighAlm` | `Alm_RoomTempHigh` | 房间温度超限 |
| 1 | `xPIDErrorAlm` | `Alm_PIDError` | PID控制器错误 |
| 2 | `xSensorFaultAlm` | `Alm_SensorFault` | 温度传感器故障模拟 |
| 3 | `xEStopAlm` | `Alm_EStop` | 模拟急停 |

PLC使用常开触点和普通线圈，把每个报警状态写到对应位。下面是新增的两个映射程序段。

![传感器故障和模拟急停分别映射到报警字bit 2、bit 3](/images/posts/d1-hmi-alarm-management/02-bit-mapping.png)

`wHMIAlarmTrigger.%X2`表示访问这个Word的第2位。映射线圈使用普通线圈，使报警位跟随源变量；锁存已经在前面的报警逻辑中完成。

这种方法便于集中维护点表。扩展时要保证PLC位号与HMI触发位一致，也要避免其他程序段再给整个报警字赋值，覆盖已写入的位。

### HMI变量连接

![HMI变量表：报警触发字使用Word和100 ms采集周期](/images/posts/d1-hmi-alarm-management/03-hmi-tags.png)

本项目采用符号访问，HMI连接为 `HMI_Conn_PLC1`。选择对应PLC变量后，不需要再手填DB绝对地址。

报警字采集周期设为100 ms。它表示HMI读取数据的周期，不代表PLC联锁执行周期，也不等于归档记录周期。停机和加热禁止仍由PLC逻辑处理。

对于持续时间很短的事件，单纯缩短HMI采集周期不一定能保证捕获。本项目把故障锁存在PLC中，使HMI有机会读到稳定的报警状态。

## 4. 离散报警怎样配置

![四条离散报警：共用触发变量，分别使用bit 0至bit 3](/images/posts/d1-hmi-alarm-management/04-discrete-alarms.png)

在HMI的“离散量报警”中，每一行定义一条报警。此次四条报警共用 `wHMIAlarmTrigger`，类别均为 `Errors`，触发位分别为0、1、2、3，HMI确认变量留空。

| 配置项 | 配置时关注的问题 |
|---|---|
| 报警名称与编号 | 是否便于定位，是否与其他报警重复 |
| 报警文本 | 能否说明发生了什么、设备处于什么状态 |
| 报警类别 | 确认要求和显示样式是否符合用途 |
| 触发变量与位 | 是否对应PLC真实报警位 |
| 报警视图 | 是否包含所需类别，当前显示哪类数据 |

例如“温度传感器故障（模拟），加热已禁止”同时说明了故障对象和联锁动作。报警类别本身不会替PLC执行停机，联锁必须由控制程序实现。

离散报警关注某个位的状态；模拟量报警则围绕数值与限值配置。选择哪一种，要看报警判断放在哪里。本项目沿用PLC生成的布尔报警，再打包到Word中供HMI读取。

## 5. 锁存与复位：故障还在，就不能复位

新增变量分成命令和报警两组：

| 变量 | 类型 | 用途 |
|---|---|---|
| `xSimSensorFaultCmd` | Bool | 注入传感器故障模拟信号 |
| `xSimEStopCmd` | Bool | 注入模拟急停信号 |
| `xSensorFaultAlm` | Bool | 锁存传感器故障报警 |
| `xEStopAlm` | Bool | 锁存模拟急停报警 |

![新增报警的置位和条件复位逻辑](/images/posts/d1-hmi-alarm-management/05-latch-reset.png)

以传感器故障为例，`xSimSensorFaultCmd`成立时置位 `xSensorFaultAlm`。复位支路要求 `xAlarmResetCmd`成立，同时故障模拟信号已经撤销。

因此，原始故障信号关闭后，锁存报警不会立刻消失；还需要执行PLC报警复位。对HMI而言，它监视的是锁存后的报警位，报警“离开”的时刻也就取决于该报警位何时回到0。

原有超温报警沿用80℃置位、降至75℃及以下才允许手动复位的条件。这让故障触发阈值和允许复位阈值分开，避免在同一个温度点附近反复切换。

### 报警接入原有加热联锁

![四个报警常闭触点串联，生成系统就绪状态](/images/posts/d1-hmi-alarm-management/06-ready-interlock.png)

四类报警都接入 `xSystemReadySts` 的生成条件。任一报警存在，系统就绪撤销；后续原有逻辑复位运行状态、撤销加热允许，并通过SEL把 `rHeaterOutSafePct` 选择为0。

故障处理和报警显示共用同一组状态来源，便于从PLC到HMI逐级检查。

## 6. 复用报警视图，理解显示的数据

![沿用B2报警画面，增加故障模拟操作入口](/images/posts/d1-hmi-alarm-management/07-alarm-screen.png)

原来的 `Scr_B2_Alarms` 已经有报警视图、确认操作和返回主画面的按钮，这次直接复用。新增模拟入口后，可以在同一个画面观察报警变化。

报警显示需要同时理解两个维度：一是报警条件是否仍存在，二是操作员是否已经确认。

| 情况 | 含义 |
|---|---|
| 条件存在、未确认 | 故障仍有效，尚未确认收到 |
| 条件存在、已确认 | 操作员已看到，但故障仍未解除 |
| 条件消失、未确认 | 故障条件已解除，但仍可能需要确认 |
| 条件消失、已确认 | 这一轮报警处理结束，事件可能仍保留在记录中 |

具体显示的文字、符号、颜色和保留方式受报警类别与视图设置影响。判断状态时应结合配置，而不是只记一种颜色或一个字母。

### 当前报警、缓冲区、归档不是同一件事

| 数据来源 | 主要用途 | 需要注意 |
|---|---|---|
| 当前报警 | 查看仍有效或仍待处理的报警 | 显示结果受确认规则和筛选条件影响 |
| 报警缓冲区 | 查看运行期间的报警事件 | 容量有限，不能直接当作长期保存方案 |
| 报警归档 | 按配置把事件保存到存储介质 | 需要单独配置路径、记录策略、容量等 |

本次完成的是报警触发、显示、确认与复位，以及运行期间的事件查看。长期保存报警数据需要另行配置报警归档。即使页面标题叫“报警记录”，也要检查数据源，才能判断这些记录实际存在哪里。

## 7. 一套可复用的排查顺序

遇到报警没有显示时，我按下面的顺序检查：

1. 原始故障条件是否成立，PLC报警变量是否置位。
2. `wHMIAlarmTrigger`对应位是否变为1。
3. HMI变量是否连接到正确的PLC和数据块成员。
4. 离散报警的触发变量与触发位是否匹配。
5. 报警视图是否勾选相应类别，筛选条件是否隐藏了报警。

如果确认后设备仍不能启动，则继续检查PLC报警是否已复位、原故障是否解除、系统就绪是否恢复。HMI确认和PLC复位属于不同动作，不能混在一起判断。

## 8. D1学习收获

D1让我把注意力从“再加一条报警程序”转向HMI报警管理本身。报警字解决数据组织问题，报警类别和视图决定信息怎样呈现，确认与复位明确操作职责，缓冲区与归档则决定事件如何保存。

这次基于已有B2工程完成了四类报警组态和两种故障模拟，原来的PID与温度模型继续作为数据来源。后续D2会重点学习过程值记录与历史趋势，D3学习整组工艺参数的配方管理。
